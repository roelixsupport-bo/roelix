# ROELIX local storefront

ROELIX uses Supabase for dashboard authentication, submitted orders, and the client-facing assistant's published product catalogue and shipping rates. Cart contents, wishlist, analytics, and settings remain in the current browser's local storage.

## Run locally

Install dependencies with npm, then start the development server:

```sh
npm install
npm run dev
```

The server listens on `127.0.0.1:8081` and selects the next available port if that port is occupied.

## Dashboard roles

Configure `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY`, then apply the SQL migrations in `supabase/migrations`. The confirmed `roelix.support@gmail.com` account is assigned the `admin` role; newly created Supabase Auth users receive the `staff` role. Create staff credentials through Supabase Auth and share them with the staff member securely.

Staff can view cloud orders and update their statuses. Admins additionally manage products in Supabase and access local subscribers, analytics, and settings. Database row-level security and a database trigger restrict staff order updates to status changes and prevent staff from deleting orders. The primary administrator can manage profile roles from the Supabase SQL editor.

## Local features and limitations

- The first Admin dashboard load seeds the Supabase product catalogue from that browser's current ROELIX catalogue if the cloud catalogue is empty. Product changes made in the Admin dashboard are saved to Supabase and the current browser.
- Checkout stores a local order and attempts to insert the order into Supabase. Card choices are not charged or sent to a payment processor.
- The ROELIX Luxury Home Textile Advisor reads published, in-stock products and Bosta governorate rates from Supabase when answering product and shipping questions. It checks order status directly against Supabase using the order number and checkout phone number; the database function returns only the order status and total, and the phone is masked in the saved conversation. Apply all migrations before using these assistant features. Responses are rule-based rather than generated by a hosted AI model; bespoke pricing and unconfigured policies are referred to the store team.
- Storefront analytics and admin settings remain in the same browser profile; there are no third-party tracking pixels.
- Local data is not encrypted, backed up, or shared with other devices. Clearing browser site data removes it.

Payments and hosted AI services are not configured or contacted by this application.
